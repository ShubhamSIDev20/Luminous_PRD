🖥️ 1 · Platform & Deployment
UI type ✅ ⚠️ BTS runs in any modern browser over HTTP; BM4 is a Windows desktop application that must be installed on each workstation
Remote / multi-site access ✅ ⚠️ BTS: accessible from any device on the LAN via browser; BM4: supports networked workstations but requires Windows WKS install or internet configuration
Operating system ✅ ❌ BTS runs on Linux (Docker container) or any .NET 8 host; BM4 is Windows-only
Containerization (Docker) ✅ ❌ BTS ships with a Dockerfile and docker-compose.yml; auto-restarts on crash via Docker restart policy
Database engine ✅ ⚠️ BTS uses lightweight SQLite (main DB + per-session files); BM4 requires a licensed Microsoft SQL Server instance with periodic maintenance and compaction
Multi-user simultaneous access ✅ ✅ Both support concurrent users; BTS handles it via Blazor SignalR sessions
CI/CD & automated deployment ✅ ❌ BTS uses GitHub Actions to build, publish, and push Docker image on every commit to main; BM4 is manually installed
🔌 2 · Circuit / Channel Control
Start circuit ✅ ✅ Both support starting single or multiple circuits; BM4 also offers a start wizard with richer options
Stop circuit ✅ ✅ Both support stopping one or many circuits simultaneously
Pause / Interrupt circuit ✅ ✅ BTS calls it "Pause" (0xEE Q03); BM4 calls it "Interrupt" — functionally the same mid-test hold
Continue / Resume circuit ✅ ✅ Both resume from pause/interrupt state
Reset circuit ✅ ✅ BTS: single reset command (0xEE Q06 system reset); BM4: two modes — soft reset (cleans Dispo only) and hard reset (resets ComServer + controller task)
Deferred (scheduled) start ❌ ✅ BM4 allows setting a future date/time for a circuit to start automatically; BTS has no scheduled start
Multi-circuit select & control ✅ ✅ Both support selecting and controlling multiple circuits in one action
Session naming scheme / tokens ❌ ✅ BM4 supports dynamic session naming with tokens: <date>, <battery>, <program>, <operator>, <inc3>, etc. BTS generates session IDs automatically
Start from specific step number ❌ ✅ BM4 allows choosing which program step to begin execution from; useful for resuming interrupted programs
100% current / percentage override at start ❌ ✅ BM4 lets operators define the 100% current base at start time; percentage operators in the program are resolved against this value
📋 3 · Program Management
Step types: Charge CC/CV, Discharge, Rest ✅ ✅ Core step types available in both; BM4 supports additional types (ramp functions, SYN synchronisation, formation schedules)
Cycle steps (loops) ✅ ✅ Both support repeat/cycle blocks within a program
Program upload to hardware ✅ ✅ BTS: binary upload via TCP 0xBB protocol (steps count then step data); BM4: via ComServer to hardware
Reusable procedures (sub-programs) ❌ ✅ BM4 (BTS-600) supports named procedures that can be called from programs; BTS has no sub-program concept
GOTO / counter / special label commands ❌ ✅ BM4 supports GOTO statements, counter settings, and special labels for complex branching logic in programs
Certified / locked programs ❌ ✅ BM4 supports program certification — certified programs can only be modified by users with the Certificator right
Multiple hardware program formats ⚠️ ✅ BTS supports one hardware family (custom BTS); BM4 supports BTS-600, MF-2000, BTS-500, PLT, and BAFOS — each with their own program editor
DBC / CAN file upload to hardware ✅ ❌ BTS parses DBC CAN files and uploads channel mappings to hardware via TCP 0xBB Q07/Q08; BM4 does not have DBC support
Battery parameter–based nominal values (ACN, CNom) ⚠️ ✅ BM4 supports ACN (current as fraction of nominal capacity), ACNX, CNom, and VNC operators in programs; BTS uses fixed values
🔋 4 · Battery Management
Battery CRUD (add / edit / delete) ✅ ✅ Both provide full create/read/update/delete for battery records
Battery type / chemistry ✅ ✅ Both support categorizing batteries by type; BTS tracks chemistry field
Nominal capacity, serial number ✅ ✅ Core fields available in both
Bulk battery creation ❌ ✅ BM4 allows creating up to 100 batteries at once with auto-incremented names; BTS requires individual entry
Cell count, gassing voltage, charge factor ❌ ✅ BM4 stores extended battery parameters used in program calculations (VNC, CNom); BTS stores capacity/chemistry but not these electrochemical parameters
Push battery params to hardware ✅ ✅ BTS: via TCP 0xAA Q05 Write Battery Params; BM4: via ComServer
Link battery to test session ✅ ✅ Both associate a battery record with each test session
📡 5 · Real-Time Monitoring
Live voltage, current, temperature ✅ ✅ Both display live electrical measurements continuously during a test
Live power, capacity, energy ✅ ✅ BTS reports Accumulated, Charge, Discharge, and Step variants for capacity and energy
Circuit status display ✅ ✅ Both use color-coded status (Idle, Charge, Discharge, Pause, Error, Offline); BTS maps 9 states via CircuitStatus enum
Error code display ✅ ✅ BTS shows ErrorId byte + 17-bit SystemErrorId bitmask; BM4 shows ER1–ER10 error codes in status column
Digital I/O state display ✅ ❌ BTS displays 3-byte IO status from the real-time UDP packet; BM4 does not expose digital I/O states in the UI
Live data push mechanism ✅ ⚠️ BTS: Blazor SignalR push via UDP→InvokeAsync(StateHasChanged), <500ms latency; BM4: ComServer polling, Windows message-based
Multi-circuit overview dashboard ✅ ✅ BTS: responsive grid dashboard per registered circuit; BM4: Floor Display (graphical layout) and Status View (grid)
QuickView hover popup ❌ ✅ BM4: hovering over a circuit block shows a mini status popup with circuit name, status, battery type; auto-updated
QuattroView (4-panel detail) ❌ ✅ BM4: double-clicking a circuit opens a 4-panel view (QuickView + graph + running program + registration data); BTS shows circuit data on a dedicated page
Step number & cycle counter ✅ ✅ BTS: StepNumber, CycleNumber, TableStepNumber in the 79-byte real-time packet; BM4 displays in Status View
DBC / CAN signal live display ✅ ❌ BTS decodes and displays live CAN bus signals mapped via DBC files alongside standard measurements
💾 6 · Data Storage & History
Session data persistence ✅ ✅ BTS: per-session SQLite file at {date}/{SessionID}_{DeviceID}_{CircuitID}.db; BM4: SQL Server registration tables
High-frequency async write queue ✅ ⚠️ BTS uses .NET Channel<T> to decouple UDP receive from disk write — lock-free, burst-tolerant; BM4 relies on ComServer buffering
Export to Excel ✅ ✅ Both support exporting historical session data to Excel format
Filter & search historical data ✅ ✅ Both provide filtering on historical registration data
Delete session data ✅ ✅ Both allow removing old session records; BM4 recommends periodic deletion to manage SQL Server DB size
Database archive viewer ❌ ✅ BM4 has a dedicated Database Archive Viewer for browsing archived historical databases; BTS has no archiving concept
Automated DB backup scripts ⚠️ ✅ BM4 ships with scheduled backup scripts for SQL Server; BTS relies on Docker volume backup (host-level, not built-in)
DBC CAN signal recording ✅ ❌ BTS records decoded CAN signals as opcode-keyed rows (0x1F–0xFA) in the session SQLite DB alongside standard measurements

Historical data graphs ✅ ✅ Both plot historical measurement data as graphs; BTS via DataViewer component, BM4 via Registration Data graphical display
Live charting during test ✅ ⚠️ BTS has live charts updating in real-time on the dashboard; BM4 shows a live graph inside QuattroView only
EIS-Meter data graphs ❌ ✅ BM4 has a dedicated graphical display for EIS impedance spectroscopy meter data; BTS does not support EIS hardware
Graph zoom controls ✅ ✅ BM4 has extensive zoom (50%/75%/100%/200%/custom/fit) on all charts; BTS has chart interaction
Print graphs ❌ ✅ BM4 supports printing registration data graphs with header/footer configuration; BTS has no print-specific graph export
DBC CAN signal graphs ✅ ❌ BTS can plot decoded CAN bus signals from DBC files on the same timeline as electrical measurements
👤 8 · User & Access Management
Authentication ✅ ✅ BTS: ASP.NET Identity (email + password, PBKDF2 hashed); BM4: internal BM credential store (username + password)
Role-based access control ✅ ✅ BTS: 3 roles (Administrator, Operator, Viewer); BM4: Departments → Groups → Users with individual right toggles
Granular per-right permissions ⚠️ ✅ BM4 allows toggling each individual right (Start, Stop, Add Program, Export, etc.) per user/group; BTS has coarser role-based access
Per-circuit access control ✅ ❌ BTS UserCircuitAccess table restricts which circuits each user can operate; BM4 controls rights globally, not per circuit
Audit logs ✅ ✅ BTS: AuditLogs DB table + Serilog rolling files; BM4: Event Viewer with Workstation, ComServer, and Service tabs
Inactivity auto-logout ❌ ✅ BM4 supports configurable inactivity timeout per user/department (default 10 min); BTS sessions do not auto-expire
In-app log viewer ✅ ✅ BTS: log tail accessible via REST /api/Device/logs and in-app UI; BM4: Event Viewer with filter, sort, copy, and per-tab icons
Password encryption / hashing ✅ ⚠️ BTS: PBKDF2 via ASP.NET Identity; BM4 uses internal BM credential store — hashing details not publicly documented
🔧 9 · Hardware Support
Supported hardware families ⚠️ ✅ BTS is designed for a single custom hardware family; BM4 supports BTS-600, MF-2000 (Formation Supervisor III), BTS-500, PLT (Production Line Testing), and BAFOS
Automatic device discovery (broadcast) ✅ ❌ BTS uses SADP (Simple Automatic Device Protocol): UDP broadcast on port 10002, devices reply on 10003 with full network config; BM4 requires manual ComServer configuration
Remote IP configuration push ✅ ❌ BTS can push IP address, subnet, gateway, DNS, and server config (Q4/Q5) to a device over UDP broadcast; BM4 cannot remotely configure device network settings
Hardware calibration ✅ ⚠️ BTS has a dedicated calibration protocol (0xA0) with 20 query types for current/voltage low point, high point, gain/offset, and verification; BM4 mentions calibration indirectly
External device support (temp chambers, scales) ❌ ✅ BM4 integrates external instruments (temperature chambers, scales, EIS-Meter, RE-Series) into the same database; BTS is limited to its own hardware
Hardware profile save/restore ❌ ✅ BM4 (BTS-600) supports saving and restoring circuit channel profiles; BTS has no profile concept
N concurrent devices ✅ ✅ Both architectures support multiple simultaneous hardware devices
📶 10 · Communication Protocols
TCP command channel ✅ ✅ BTS: persistent TCP on port 9999 with binary framing (StartByte + DeviceID + CircuitID + QueryID + Payload + CRC-16); BM4: Partyline via ComServer
UDP real-time data stream ✅ ⚠️ BTS: hardware streams 79-byte packets to port 10000 continuously; BM4 uses ComServer polling, not direct UDP streaming
UDP high-frequency session store ✅ ❌ BTS: dedicated UDP port 10001 for batched measurement record storage with opcode-tagged fields; BM4 stores through ComServer to SQL Server
UDP broadcast device discovery ✅ ❌ BTS: SADP on ports 10002/10003; no equivalent in BM4
CRC-16/Modbus packet integrity ✅ ⚠️ BTS appends CRC-16/Modbus (poly 0xA001, init 0xFFFF) to every packet; BM4 protocol details not publicly specified
DBC / CAN bus decoding ✅ ⚠️ BTS has a full DBC parser (DecoderService) that maps CAN signals to opcode channels; BM4 only reports CAN bus errors (ER7/ER8) without signal decoding
OPC protocol support ❌ ✅ BM4 supports OPC (ER10 reports OPC errors); BTS has no OPC integration
SignalR / WebSocket browser push ✅ ❌ BTS pushes UI updates over ASP.NET Core SignalR (WebSocket); BM4 is a native desktop app with no WebSocket layer
🤖 11 · API & Integration
REST API ✅ ❌ BTS exposes a JWT-secured REST API at /api/Device/* for all circuit operations, live data, programs, and batteries; BM4 has no REST API
MCP / AI assistant tools ✅ ❌ BTS exposes an MCP server at /mcp (HTTP SSE) — AI assistants (Claude Desktop etc.) can start/stop tests, get live data, and send programs using natural language
Server-Sent Events (SSE) live stream ✅ ❌ BTS: GET /api/Device/GetLiveSSE?deviceID=1&circuitID=1 streams real-time JSON continuously to any HTTP client
Programmatic circuit control (external) ✅ ❌ BTS REST API allows external systems, scripts, or AI agents to start, stop, pause, and query circuits; BM4 has no external control interface
OPC integration (external SCADA) ❌ ✅ BM4 supports OPC for integration with SCADA / industrial control systems; BTS has no OPC layer
